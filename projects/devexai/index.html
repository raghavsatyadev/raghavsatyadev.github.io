DevExAI: a company's AI toolsmith.

Every week someone finds a trick that makes AI coding better: a prompt, a skill, an MCP server, a GitHub project. It usually stays with one person. DevExAI turns that idea into a tool the whole company can install with one command, and credits the person who had it.

The pipeline

How an idea moves

Every step is posted in a Slack thread just for that idea, so the person with the idea and their maintainer see everything the bot does and why.

  1. Share an idea

    A DM, the #ai-ideas channel or /devex-idea. Text, links or both. The bot replies with a tracking number and opens a thread. Exact repeats are caught; near-repeats go to the maintainer.

  2. Safety check

    An AI reviewer reads the idea and every linked page. Pass, unsure (maintainer decides) or reject with a polite reason. Nothing starts before this.

  3. Research

    Links are fetched by a separate worker with no access to keys. The planner also reads short descriptions of the company's own projects, so it builds what teams need.

  4. Plan with Claude Opus

    What will be built, for which assistant, what it needs, how it is tested and how big it is, in plain words.

  5. Maintainer approves

    The plan arrives as a DM with Approve, Suggest change and Stop. Anything paid or behind a login always needs a person's yes.

  6. AI builds

    The builder writes the tool's files, tests and a short README, saved on the idea's page.

  7. Opus reviews

    A second AI checks the work against the plan. If it finds problems, the builder gets one more try. No AI ever reviews its own work.

  8. Final yes

    A maintainer reads the code. Nothing reaches colleagues without this.

  9. Publish and thank

    A short post goes up on the built-in blog with an Install button and "Idea by @name", and the bot thanks the person in the thread.

Bundles

One package that installs several of the above.

# this project (default)
devexai install <tool>
# every project on this computer
devexai install <tool> --global
# remove it cleanly
devexai uninstall <tool>

The installer shows exactly what it will add and asks first. It never runs the tool's code, never edits settings files, and keeps files you changed when you uninstall. Developers get it from a Windows setup exe with no Python or admin rights, a one-line Linux script, or a single Python file.

Guardrails

Rules the bot always follows

An AI that writes code for a whole company needs hard limits. The key ones are enforced in code, not just asked for in a prompt.

  1. Nothing starts until the safety check passes.
  2. Nothing that costs money, needs a login, or gets released happens without a maintainer's yes.
  3. Claude Opus checks every line of code before a person sees it.
  4. The bot can only read company code and project descriptions, and never sends them to unapproved services.
  5. Web pages and messages are reading material, never orders. Hidden prompt injections are flagged.
  6. Everything the bot does is written in the idea's thread.
  7. Every tool can be removed cleanly.

Engineering

Under the hood

Lean Python core

Two runtime dependencies (slack-sdk and cryptography). The dashboard, blog and auth are served by DevExAI itself.

Swappable parts

Chat app, AI provider, code host, secret store and blog are behind interfaces chosen in one settings file. Slack and Claude today.

Isolated link fetching

A separate worker reads links as plain text with no access to keys, so a poisoned page can't reach secrets.

Installers and updates

Admin and developer setup exes for Windows, a Linux developer command, a tray app, and a self-updater that verifies Ed25519-signed update manifests.

Replay mode

Model calls can be recorded and replayed, which powers the demos; tests use replays and a stub model, so they run fast and cost nothing.

Built with Claude Code

Written in three days with Claude Code as pair programmer, from the PRD and slide deck to installers. More in the blog post.
